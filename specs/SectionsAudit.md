# SectionsAudit — аудит разделов ДС

Рабочая страница инициативы «ДС из коробки» (RFC, раздел «Правила и паттерны»). Не переиспользуемый компонент: фиксирует три фазы переноса переиспользуемого поведения и композиционных стилей с витрины (playground-обёртки `*.page.js`, инлайн `<style>`) в глобальный рантайм/CSS.

## Разделы страницы
- **Дорожная карта** — три фазы, порядок фиксирован.
- **Фаза 1** — правки существующих компонентов: визуальная выверка глазами по макетам в Pixso. Только описание фазы, таблицы/лога нет — правки не протоколируются на странице.
- **Парность документации и кода** — параллельный трек, не фаза: расхождения сниппетов документации с фактическим CSS (массив `PARITY`, находится скриптом) + подраздел «Сверка 10 экранов с ДС» с методом замера и выводами.
- **Фаза 2** — недостающие компоненты относительно типового enterprise-набора.
- **Фаза 3** — в чём проблема: диагностика, что рантайм-поведение и композиционный CSS сейчас живут только на витрине.
- **Матрица «из коробки»** — по каждому компоненту ДС: нужен ли рантайм, где он живёт сейчас, где живёт композиционный CSS.
- **План экстракции** — по компоненту за раз, проверка на живом экране (мокапе), не на витрине; включает шаг и панель «Гейт парности документации и кода» (проверка скриптом, что каждый класс из сниппетов существует в CSS).
- **Порядок работ** — приоритет по частоте использования на экранах и по разблокировке зависимых компонентов; первым рядом идёт парность (после текущих UI-правок компонентов, до экстракции рантайма).

## Обновление
Спека — ориентир по структуре страницы, не источник содержимого. При закрытии фазы обновляй таблицы `#parity` / `#missing` и матрицу прямо на странице; эту спеку — только если меняется структура разделов.
