# Приёмка экрана

Проверка идёт по файлу `pages/screens/genOD/<Имя>.html` и по
`<Имя>.screen.md`. Вердикт один: **PASS** или **NEEDS-WORK**. Любой невыполненный
пункт группы «Блокеры» даёт NEEDS-WORK.

## Быстрая механическая проверка

Эти команды находят большую часть дефектов за один проход:

```bash
F=pages/screens/genOD/ИмяЭкрана.html

grep -n "<svg"            $F   # должно быть пусто — иконки только <i data-icon>
grep -n "#[0-9a-fA-F]\{3,6\}" $F   # должно быть пусто — цвета только токенами
grep -n "rgb(\|rgba("     $F   # должно быть пусто
grep -n "styles/"         $F   # должно быть пусто — подключается только ds.css
grep -n "scripts/ds-"     $F   # должно быть пусто — подключается только ds.js
grep -c "ds.css"          $F   # ровно 1
grep -c "scripts/ds.js"   $F   # ровно 1
grep -n "\.\./\.\./[^.]"  $F   # пути должны быть ../../../ (три уровня)
grep -n "Lorem\|TODO\|XXX\|здесь будет\|заглушк" $F   # должно быть пусто

# --- изобретённое вместо готового (Б14, Б16) ---
grep -n "grid-column: *span" $F      # так и должна задаваться ширина тайла
grep -n "\.[a-z-]*\(half\|full\|col[0-9]\) *{" $F   # свои классы ширины — блокер
grep -n "\.tile-row *{\|\.tile-row[^+]*margin" $F   # свой зазор между рядами — блокер

# --- вариант компонента под смысл поля (Б17) ---
grep -n "pbar--floating" $F          # рядом должно стоять «вероятность»/«скор», не «прогресс»
```

Проверка имён иконок: выпиши все `data-icon="…"` и сверь со списком в
`specs/Icons.md`.

```bash
grep -o 'data-icon="[^"]*"' $F | sort -u
```

Каждое имя обязано встречаться в `specs/Icons.md`. Не встречается — блокер.

## Проверка живости: работает ли макет

Экран не бумажный — штатное поведение компонентов ДС должно работать. Смотри,
какие компоненты есть в разметке, и требуй их хуки:

```bash
grep -c "class=\"tbl\""        $F   # есть таблица?
grep -c "data-table"           $F   # → должен быть хук
grep -c "modal-scrim"          $F   # есть модалка?
grep -c "data-modal"           $F   # → должен быть триггер
grep -c "tile--accordion"      $F ; grep -c "tile__toggle"   $F
grep -c "class=\"tabs\|segctrl" $F ; grep -c "data-tabs\|data-segctrl" $F
grep -c "riskmetric"           $F   # риск-метрика — только data-riskmetric
grep -c "data-popover"         $F
```

Компонент есть, хука нет — блокер Б13. Полная таблица соответствий —
`.opencode/skills/screen-assembly/references/runtime-hooks.md`.

Обратная проверка: `grep -n "<script" $F` — тегов должно быть один-два.
`ds.js` обязателен; второй допустим только под данные конкретного экрана.
Самописный обработчик того, что уже умеет рантайм ДС (открытие модалки,
сворачивание тайла, переключение табов), — блокер.

## Блокеры

| # | Проверка |
|---|---|
| Б1 | Подключены ровно `../../../ds.css` и `../../../scripts/ds.js`, поштучных `styles/*` и `scripts/ds-*` нет |
| Б2 | Ни одного инлайн-`<svg>`; все иконки — `<i data-icon="имя">`, все имена есть в `specs/Icons.md` |
| Б3 | Ни одного `#hex`, `rgb()`, ни одного размера шрифта/цвета мимо токенов; собственный CSS — только раскладка |
| Б4 | Все использованные классы существуют в ДС (сверить по чит-шиту компонента) |
| Б5 | Каркас на месте: `.nav-layout` → `.nav` + `.screen` → `.crumbs` + `main.screen__content`; поля 24px не переопределены |
| Б6 | Ровно один `h1`, и это `.phead__title` |
| Б7 | В каждом ряду тайлов сумма `grid-column:span N` равна 12 |
| Б8 | У таблицы `grid-template-columns` совпадает у шапки и у **всех** строк; первая и последняя ячейки — разделители |
| Б9 | Контент отрисован, а не заглушен: таблица — минимум 6 строк правдоподобных данных, тайлы заполнены |
| Б10 | Нет горизонтального выхода за границу: нет фиксированных ширин, превышающих контентную область, нет `width` в пикселях на блоках сетки |
| Б11 | Файлы ДС не изменены — правки только внутри `pages/screens/genOD/` |
| Б12 | Рядом с HTML лежит `<Имя>.screen.md` с заполненной YAML-шапкой |
| Б13 | У каждого интерактивного компонента стоит его хук рантайма (`data-table`, `data-modal`, `data-tabs`, `data-popover`, `data-riskmetric`, `.tile__toggle` и т.д.), и нет самописного JS вместо рантайма ДС |
| Б14 | **Ширина тайлов — только `style="grid-column:span N"` на `.tile`.** Свои классы ширины (`.xxx-half`, `.xxx-full`, `.xxx-col6`) — блокер: ширина перестаёт читаться из разметки |
| Б15 | **Размерные модификаторы совпадают со спекой компонента**, а не «похожи». Особо: бургер/пин/выход NavPanel — `ibtn--m`; действия в шапке тайла — `ibtn--m`; футерные кнопки DatePicker — `btn--xs` |
| Б16 | **Зазоры не выставлены руками там, где их держит компонент.** Между рядами тайлов свой `margin`/`gap` — блокер (`.tile-row + .tile-row` = 16px уже в CSS). 24px (`--layout-block-gap`) допустим только между крупными зонами экрана |
| Б17 | **Именованное поле с прогресс-баром — обычный вариант `.pbar__head`** (подпись слева, значение справа), независимо от названия поля. `pbar--floating` допустим только там, где подписи-заголовка нет по построению (одиночная шкала, бар в строке таблицы). Floating у поля с подписью — блокер: подпись уезжает под трек, значение встаёт слева, поле расходится с соседними |
| Б20 | **Однотипные показатели внутри одного блока оформлены одинаково.** Два бара в одном тайле (Прогресс и Вероятность) не могут быть один обычным, другой floating; поле-значение и поле-бар для однородных величин не смешиваются |
| Б18 | **Элемент на всю ширину сетки тайла — внутри `.tile__grid` с классом `.tile__grid-full`**, а не соседним блоком со своими паддингами |
| Б19 | **Иконка выбрана по смыслу действия.** Переход во внешнюю систему (HR, реестр другой системы) — `arrow-up-right`, не та же `arrow-right`, что у внутренних переходов |

## Замечания

| # | Проверка |
|---|---|
| З1 | Статусы оформлены компонентом Chip, а не текстом; счётчики — Badge |
| З2 | Сортировка активна максимум у одной колонки, `aria-sort` проставлен |
| З3 | У каждой кнопки-иконки есть `aria-label` |
| З4 | Числа в таблице — в ячейках `tc--numbers`, формат `1 240 500,00` |
| З5 | Даты в формате `ДД.ММ.ГГГГ`, пустое значение — `—` |
| З6 | В шапке страницы не больше 3 кнопок, главная — `btn--accent`, ровно одна |
| З7 | Модалки лежат в конце `body` с `hidden`, триггеры помечены `data-modal` |
| З8 | Тексты на русском, действия в инфинитиве («Добавить», не «Добавление») |
| З9 | Описано состояние «данных нет» — компонентом EmptyState или `.dtable__empty` |
| З10 | Есть `@container screen (max-width: …)` для перестроения, если на экране больше одного ряда тайлов |

## Полнота относительно ТЗ

Если путь к ТЗ известен — пройди по нему пункт за пунктом и заполни:

- реализовано;
- реализовано с допущением (какое именно допущение);
- **не реализовано** (почему).

Ненайденный в экране пункт ТЗ — это не мелочь: он идёт в отчёт отдельной
строкой. Молча сузить объём нельзя.

## Формат вывода

```
ВЕРДИКТ: PASS | NEEDS-WORK

БЛОКЕРЫ
1. <строка N> — <что не так> → <как чинить>

ЗАМЕЧАНИЯ
1. ...

ПРОПУЩЕНО ИЗ ТЗ
- ...
```

Пустые разделы не выводить. Каждая претензия — с номером строки и цитатой.
Претензия без цитаты дефектом не считается.
